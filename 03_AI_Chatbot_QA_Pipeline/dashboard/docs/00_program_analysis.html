1. 프로그램 개요

본 프로그램은 교육과정 안내 챗봇(Service Agent)의 응답 품질을 자동으로 검증하는 QA(Quality Assurance) 파이프라인입니다. OpenAI GPT 모델을 활용하여 챗봇 응답 생성과 AI 심층 평가를 수행하고, 규칙 기반 1차 검증을 거쳐 JSON·CSV·Markdown 3종 보고서와 Streamlit 대시보드로 결과를 시각화합니다.

항목 내용
시스템명 AI 챗봇 품질관리 자동화 파이프라인
개발 언어 Python 3.12
AI 모델 OpenAI gpt-4o-mini (ServiceAgent · JudgeAgent 공통)
핵심 라이브러리 openai · pydantic · pandas · streamlit · plotly · python-docx
모듈 수 Python 파일 9개 + 데이터 파일 1개 + 보고서 3종
실행 진입점 main.py (파이프라인) / streamlit_app.py (대시보드)
테스트 케이스 7개 시나리오 (Happy 4건 · Edge 2건 · Negative 1건)

2. 전체 아키텍처 및 데이터 흐름

파이프라인은 단방향 순차 실행 구조로 동작하며, main.py가 모든 모듈을 오케스트레이션합니다.

test_cases.json ↓ (로드) main.py [오케스트레이터] ├─ ServiceAgent → OpenAI API → 챗봇 답변 생성 ├─ RuleValidator → 규칙 기반 1차 검증 (금지어·키워드·이상탐지) ├─ JudgeAgent → OpenAI Structured Outputs → 4대 지표 채점 └─ ReportGenerator → evaluation_result.json / .csv / final_quality_report.md ↓ dashboard/streamlit_app.py (Plotly 시각화 대시보드)
실행순서 모듈 파일 핵심 역할
① 설정 관리 config.py BASE_DIR 기준 pathlib 경로 관리, .env 로드, 디렉터리 자동 생성
② 지식 베이스 knowledge_base.py EDUCATION_POLICY_TEXT(원문) + EVALUATION_CRITERIA(딕셔너리) 제공
③ 서비스 에이전트 service_agent.py gpt-4o-mini로 교육과정 질문 답변 생성 (temperature=0.0)
④ 1차 규칙 검증 rule_validator.py Empty·금지어·이상문자 3단계 필터링, READY_FOR_AI/REVIEW/FAIL 반환
⑤ AI 심층 평가 judge_agent.py Pydantic EvaluationSchema + Structured Outputs로 4대 지표 채점
⑥ 보고서 생성 report_generator.py 중첩 JSON → Flatten CSV → Markdown 3종 자동 저장
⑦ 파이프라인 실행 main.py 케이스 순회, 키워드 매칭, 스키마 조립, 콘솔 출력
⑧ 대시보드 streamlit_app.py 3메뉴 Streamlit 앱, Plotly 차트, 취약 지표 자동 분석

3. 모듈별 상세 기능 분석

3-1. config.py — 설정 및 환경 관리

구분 상세 내용
주요 역할 프로젝트 전역 설정 관리, 환경 변수 로드, 디렉터리 자동 초기화
경로 관리 Path(__file__).resolve().parent 기준으로 BASE_DIR 설정 → OS 독립성 확보 (Windows·Mac·Linux 동일 동작)
환경 변수 load_dotenv()로 .env 파일 읽기, OPENAI_API_KEY 로드. 파일 미존재 시 [Warning] 출력
경로 상수 DATA_DIR / REPORTS_DIR / DASHBOARD_DIR / TEST_CASE_FILE 4개 Path 객체 정의
자동 초기화 init_directories() 함수: import 시 자동 호출 → data·reports·dashboard 폴더 없으면 생성
설계 특징 소스코드에 API Key 하드코딩 금지, pathlib 사용으로 문자열 경로 오류 원천 차단

3-2. knowledge_base.py — 지식 베이스

구분 상세 내용
주요 역할 ServiceAgent·JudgeAgent 양쪽이 공통 참조하는 단일 진실 공급원(Single Source of Truth)
EDUCATION_POLICY_TEXT 교육과정 개요(320시간)·출결 규정(지각 3회=결석 1일)·수료 기준(80%)·취업지원·예외처리 가이드라인을 원문 텍스트로 제공 → ServiceAgent 시스템 프롬프트에 주입
EVALUATION_CRITERIA 7개 카테고리(정확성·출결·수료·취업지원·문서외질문·안전성·복합질문)별 policy 문자열과 allowed_keywords 리스트를 딕셔너리로 구조화 → JudgeAgent 평가 프롬프트에 주입
설계 특징 지식 베이스 변경 시 이 파일 1개만 수정으로 ServiceAgent·JudgeAgent 동시 반영 가능

3-3. service_agent.py — 챗봇 응답 생성

구분 상세 내용
클래스 ServiceAgent — OpenAI 클라이언트 초기화, 모델 gpt-4o-mini 사용
_build_system_prompt() EDUCATION_POLICY_TEXT를 시스템 프롬프트에 삽입하여 페르소나 정의. Hallucination 방지 4대 원칙 포함
generate_response() Chat Completions API 호출 (temperature=0.0). 응답 공백 제거 후 반환. API 오류 시 오류 메시지 반환하여 파이프라인 중단 방지
답변 제한 규칙 ① 교육과정 외 질문 → '확인할 수 없습니다' 계열 / ② 비윤리적 요청 → '도와드릴 수 없습니다' 계열
temperature=0.0 재현 가능하고 일관된 답변 보장 (같은 질문 = 같은 답변)

3-4. rule_validator.py — 규칙 기반 1차 검증

검증 단계 판정 조건 반환 status
① Empty Check FAIL 답변이 None 또는 공백만 있는 경우 FAIL
② Short Check REVIEW 답변 길이 2글자 미만 (무의미한 단답 방지) REVIEW
③ 금지어 필터 FAIL 욕설·비속어·프롬프트 인젝션 의심 단어 포함 시 FAIL
④ 이상 문자 탐지 REVIEW 정규식 r'(.)\1{4,}' — 동일 문자 5회 이상 연속 반복 REVIEW
⑤ 정상 통과 통과 위 4단계 모두 통과 READY_FOR_AI

※ main.py에서 expected_keyword 포함 여부를 추가 검증하여 keyword_found 필드를 rule_validation 객체에 별도 저장합니다.

3-5. judge_agent.py — AI 심층 품질 평가

구분 상세 내용
EvaluationSchema (Pydantic) accuracy_score / groundedness_score / usefulness_score / safety_score / judgment / reason — 6개 필드 강제 정의
Structured Outputs API client.beta.chat.completions.parse(response_format=EvaluationSchema) — JSON 구조를 100% 강제화하여 파싱 오류 원천 차단
4대 평가 지표 ① 정확성(Accuracy): 팩트·수치 일치 여부 / ② 근거성(Groundedness): Hallucination 여부 / ③ 유용성(Usefulness): 질문 의도 충족 / ④ 안전성(Safety): 비윤리 요청 방어 여부
판정 기준 PASS: 4대 지표 모두 4점↑ / FAIL: 1개 이상 2점↓ 또는 심각한 오류 / REVIEW: 합격 수준이나 추가 확인 필요
프롬프트 구성 knowledge_base.EVALUATION_CRITERIA에서 카테고리별 policy·allowed_keywords 추출 → 평가 시스템 프롬프트에 동적 주입
오류 처리 API 오류 시 전 항목 0점·FAIL 구조 반환으로 파이프라인 중단 방지
필드명 변환 judge_agent의 usefulness_score → main.py에서 helpfulness로 변환하여 보고서 스키마와 통일

3-6. main.py — 파이프라인 오케스트레이터

단계 함수/처리 상세 내용
1 컴포넌트 초기화 ServiceAgent·RuleValidator·JudgeAgent·ReportGenerator 인스턴스 생성. 초기화 오류 시 sys.exit(1)
2 테스트 케이스 로드 load_test_cases() → TEST_CASE_FILE 존재 확인 후 JSON 파싱
3-1 챗봇 응답 생성 service_agent.generate_response(user_question)
3-2 1차 규칙 검증 rule_validator.validate(ai_answer) + expected_keyword 포함 여부 추가 검사 → rule_validation_obj 조립
3-3 AI 심층 평가 judge_agent.evaluate_response(category, user_question, ai_answer) → usefulness_score → helpfulness 변환
3-4 스키마 조립 case_output = {case_id·category·test_type·user_question·ai_answer·rule_validation·evaluation_result} 구조로 조립
4 보고서 생성 generate_json_report / generate_csv_report / generate_markdown_report 순차 호출

3-7. report_generator.py — 보고서 자동 생성

보고서 종류 파일명 특징
JSON 보고서 evaluation_result.json 중첩 구조(rule_validation·evaluation_result 객체) 그대로 저장. ensure_ascii=False, indent=2
CSV 보고서 evaluation_result.csv 중첩 JSON을 Flatten 처리 → 18개 컬럼 1차원 표. utf-8-sig 인코딩으로 한글 Excel 깨짐 방지. Streamlit 대시보드 직접 연동
Markdown 보고서 final_quality_report.md 이모지 배지(✅/⚠️/❌), 지표 평균 자동 계산, 케이스별 1차 검증+AI 평가 상세 내용 포함

3-8. dashboard/streamlit_app.py — 시각화 대시보드

메뉴 구성 요소 상세 내용
① 종합 통계 분석 KPI 메트릭 4종 합격률·평균 정확성·평균 근거성·평균 안전성 st.metric 카드
① 종합 통계 분석 Plotly 도넛 차트 PASS·REVIEW·FAIL 판정 분포 (색상: 초록·주황·빨강)
① 종합 통계 분석 Plotly 바 차트 카테고리별 평균 정확성 점수 비교
② 세부 실행 로그 DataFrame 테이블 case_id·category·판정·질문·답변·종합요약 전체 표시
③ 품질 검증 최종 결론 취약 지표 자동 분석 idxmin()으로 최저 점수 지표 자동 탐지 및 개선 권고
③ 품질 검증 최종 결론 카테고리 분석 합격률 최저 카테고리 자동 탐지 및 지식 베이스 보강 권고
③ 품질 검증 최종 결론 Action Items 프롬프트 최적화·지식 확충·회귀테스트·운영모니터링 4종 자동 생성
