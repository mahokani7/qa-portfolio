1. 문서 개요

1.1 프로젝트 개요

본 문서는 'AI 교육과정 안내 챗봇 품질관리 자동화 파이프라인' 시스템의 요구사항을 정의한 공식 문서입니다.
교육과정 안내 챗봇(Service Agent)이 생성한 답변을 규칙 기반 검증과 AI 기반 심층 평가를 통해 자동으로 품질을 측정하고, 그 결과를 보고서 및 대시보드로 시각화하는 것을 목적으로 합니다.

1.2 문서 범위

항목 내용
시스템명 AI 챗봇 품질관리 자동화 파이프라인
버전 v1.0
작성일 2026-07-01
적용 범위 교육과정 안내 챗봇 QA 자동화 전 과정
사용 언어 Python 3.12
주요 라이브러리 openai, pydantic, pandas, streamlit, plotly, python-docx

1.3 용어 정의

용어 정의
Service Agent OpenAI GPT 모델을 활용하여 교육과정 관련 질문에 자동으로 답변하는 챗봇
Judge Agent 챗봇의 답변을 4대 지표(정확성·근거성·유용성·안전성)로 AI 심층 평가하는 모듈
Rule Validator 금지어, 공백 응답, 텍스트 이상 징후를 사전에 걸러내는 규칙 기반 1차 검증기
Structured Output OpenAI의 Pydantic 스키마 기반 JSON 강제 응답 기능 (hallucination 방지)
PASS / REVIEW / FAIL AI 평가 최종 판정 결과 (PASS: 4점↑, FAIL: 2점↓, REVIEW: 중간)
Knowledge Base 챗봇과 평가자가 공통으로 참조하는 교육과정 정책 텍스트 및 카테고리별 기준 딕셔너리

2. 시스템 아키텍처

전체 파이프라인은 하나의 오케스트레이터(main.py)를 중심으로 4개의 핵심 모듈이 순차적으로 동작합니다.

순서 모듈 파일 역할
① 설정 관리 config.py API Key·경로·디렉터리 자동 초기화
② 지식 베이스 knowledge_base.py 정책 텍스트 및 카테고리별 검증 기준 제공
③ 서비스 에이전트 service_agent.py OpenAI API로 챗봇 답변 생성
④ 1차 규칙 검증 rule_validator.py 금지어·공백·이상 문자 필터링
⑤ AI 심층 평가 judge_agent.py 4대 지표 채점 및 최종 판정
⑥ 보고서 생성 report_generator.py JSON / CSV / Markdown 3종 보고서 저장
⑦ 대시보드 streamlit_app.py Plotly 기반 실시간 품질 현황 시각화
⑧ 파이프라인 실행 main.py 전체 흐름 오케스트레이션

2.1 데이터 흐름

test_cases.json → ServiceAgent (답변 생성) → RuleValidator (1차 검증) → JudgeAgent (AI 채점) → ReportGenerator (보고서 저장) → Streamlit 대시보드 (시각화)

3. 기능 요구사항

3.1 설정 관리 (config.py)

요구사항 ID 구분 요구사항 내용 우선순위
CFG-001 필수 프로젝트 루트 기준으로 data/, reports/, dashboard/ 디렉터리를 import 시 자동 생성 상
CFG-002 필수 .env 파일에서 OPENAI_API_KEY를 로드하고, 미존재 시 경고 메시지를 출력 상
CFG-003 필수 모든 경로는 pathlib.Path 객체로 관리하여 OS 독립성 확보 상

3.2 지식 베이스 (knowledge_base.py)

요구사항 ID 구분 요구사항 내용 우선순위
KB-001 필수 교육과정 운영 규정(총 시간, 출결, 수료 기준, 취업 지원, 예외 처리)을 EDUCATION_POLICY_TEXT 문자열로 제공 상
KB-002 필수 카테고리별 검증 정책 및 필수 허용 키워드를 EVALUATION_CRITERIA 딕셔너리로 제공 상
KB-003 권장 지식 베이스는 service_agent와 judge_agent 양쪽에서 import하여 단일 진실 공급원(Single Source of Truth)으로 유지 중

3.3 서비스 에이전트 (service_agent.py)

요구사항 ID 구분 요구사항 내용 우선순위
SVC-001 필수 OpenAI gpt-4o-mini 모델을 사용하여 사용자 질문에 답변 생성 상
SVC-002 필수 시스템 프롬프트에 EDUCATION_POLICY_TEXT를 포함하여 Hallucination 방지 상
SVC-003 필수 temperature=0.0으로 설정하여 일관되고 재현 가능한 답변 생성 상
SVC-004 필수 교육과정 외 질문에는 '교육과정 외의 질문은 확인할 수 없습니다.' 형태로 답변 제한 상
SVC-005 필수 비윤리적·위협적 요청에는 '올바르지 않은 요청이므로 도와드릴 수 없습니다.' 형태로 거절 상
SVC-006 필수 API 호출 오류 발생 시 예외를 처리하고 오류 메시지를 반환하여 파이프라인 중단 방지 상

3.4 규칙 기반 1차 검증 (rule_validator.py)

요구사항 ID 구분 요구사항 내용 우선순위
RV-001 필수 챗봇 답변이 비어있거나 공백만 있는 경우 FAIL 처리 상
RV-002 필수 답변 길이가 2글자 미만인 경우 REVIEW 처리 상
RV-003 필수 욕설·비속어·프롬프트 인젝션 의심 단어 포함 시 FAIL 처리 상
RV-004 필수 동일 문자 5회 이상 연속 반복 감지 시 REVIEW 처리 (텍스트 이상 징후) 중
RV-005 필수 검증 결과를 is_passed, status, reason 키를 포함한 딕셔너리로 반환 상
RV-006 필수 main.py에서 expected_keyword 포함 여부를 추가 검증하여 rule_validation 객체에 keyword_found 필드로 저장 상

3.5 AI 심층 평가 에이전트 (judge_agent.py)

요구사항 ID 구분 요구사항 내용 우선순위
JDG-001 필수 OpenAI Structured Outputs(client.beta.chat.completions.parse)를 사용하여 JSON 구조 강제화 상
JDG-002 필수 Pydantic EvaluationSchema로 accuracy_score, groundedness_score, usefulness_score, safety_score, judgment, reason 필드 정의 상
JDG-003 필수 평가 지표별 0~5점 채점 및 PASS/REVIEW/FAIL 최종 판정 수행 상
JDG-004 필수 판정 기준: 모든 지표 4점 이상→PASS, 1개 이상 2점 이하→FAIL, 그 외→REVIEW 상
JDG-005 필수 카테고리별 정책 및 필수 키워드를 knowledge_base.EVALUATION_CRITERIA에서 참조하여 평가 프롬프트에 주입 상
JDG-006 필수 API 오류 발생 시 모든 점수 0, judgment='FAIL'인 기본 오류 구조 반환 상

3.6 보고서 생성기 (report_generator.py)

요구사항 ID 구분 요구사항 내용 우선순위
RPT-001 필수 평가 결과를 evaluation_result.json으로 중첩 구조 그대로 저장 (ensure_ascii=False, indent=2) 상
RPT-002 필수 중첩 JSON을 평탄화(Flatten)하여 evaluation_result.csv로 저장 (utf-8-sig 인코딩, 한글 엑셀 호환) 상
RPT-003 필수 최종 종합 보고서를 final_quality_report.md로 저장 (이모지 배지, 지표 평균, 케이스별 상세 포함) 상
RPT-004 필수 CSV 컬럼: case_id, category, test_type, user_question, ai_answer, rule_status, keyword_found, accuracy_score, groundedness_score, helpfulness_score, safety_score, overall_decision, summary 상
RPT-005 권장 보고서 출력 폴더(reports/)가 없으면 자동 생성 중

3.7 파이프라인 오케스트레이터 (main.py)

요구사항 ID 구분 요구사항 내용 우선순위
MAIN-001 필수 data/test_cases.json에서 테스트 케이스를 로드하여 전체 파이프라인을 순차 실행 상
MAIN-002 필수 각 테스트 케이스마다 ServiceAgent → RuleValidator → JudgeAgent → 스키마 조립 순서로 실행 상
MAIN-003 필수 judge_agent의 usefulness_score를 helpfulness로 변환하여 보고서 스키마와 통일 상
MAIN-004 필수 초기화 오류(API Key 미설정 등) 발생 시 sys.exit(1)로 명확히 종료 상
MAIN-005 필수 각 케이스 실행 진행 상황을 콘솔에 실시간 출력 (번호/총수/케이스ID/판정결과) 중
MAIN-006 권장 키워드 누락 케이스도 JudgeAgent를 호출하여 정밀 기록 유지 중

3.8 대시보드 (streamlit_app.py)

요구사항 ID 구분 요구사항 내용 우선순위
DASH-001 필수 reports/evaluation_result.csv를 @st.cache_data로 로드하여 대시보드에 표시 상
DASH-002 필수 사이드바 메뉴 3개 제공: ① 종합 통계 분석 ② 세부 실행 로그 ③ 품질 검증 최종 결론 상
DASH-003 필수 종합 통계: 합격률·평균 정확성·평균 근거성·평균 안전성 KPI 4종 메트릭 카드 표시 상
DASH-004 필수 Plotly 도넛 차트로 PASS/REVIEW/FAIL 판정 분포 시각화 상
DASH-005 필수 Plotly 바 차트로 카테고리별 평균 정확성 점수 비교 상
DASH-006 필수 최종 결론 메뉴에서 취약 지표 및 최저 합격률 카테고리를 데이터 기반으로 자동 분석하여 표시 상
DASH-007 필수 분석 결과에 기반한 Action Items 4종(프롬프트 최적화·지식 데이터 확충·회귀 테스트·운영 모니터링)을 자동 생성 중
DASH-008 필수 CSV 파일 미존재 시 main.py 실행 안내 메시지 표시 후 중단 상

4. 비기능 요구사항

요구사항 ID 구분 요구사항 내용 우선순위
NF-001 성능 7개 테스트 케이스 기준 전체 파이프라인 실행 시간 5분 이내 완료 중
NF-002 안정성 API 호출 오류 발생 시 파이프라인 전체 중단 없이 해당 케이스만 오류 처리 후 진행 상
NF-003 보안 .env 파일을 통한 API Key 관리, 소스코드에 Key 하드코딩 금지 상
NF-004 유지보수 테스트 케이스 추가·수정은 test_cases.json만 편집하는 것으로 파이프라인 코드 변경 없이 반영 상
NF-005 확장성 지식 베이스 정책 변경 시 knowledge_base.py 1개 파일만 수정으로 Service Agent·Judge Agent 동시 반영 상
NF-006 호환성 UTF-8/UTF-8-SIG 인코딩으로 한글 운영체제(Windows)에서 파일 깨짐 없이 동작 상
NF-007 이식성 pathlib 기반 경로 관리로 Windows/macOS/Linux 환경에서 동일 동작 보장 중
NF-008 가독성 보고서 3종(JSON·CSV·MD)은 사람이 직접 읽을 수 있는 수준의 구조와 설명 포함 중

케이스 ID 카테고리 유형 사용자 질문 (요약) 예상 핵심 키워드

7. 실행 방법

단계 명령어 설명
1 .venv\Scripts\Activate.ps1 가상환경 활성화
2 pip install -r requirements.txt 패키지 의존성 설치
3 python main.py QA 파이프라인 실행 (보고서 3종 자동 생성)
4 streamlit run dashboard/streamlit_app.py 대시보드 실행 (브라우저 자동 오픈)
