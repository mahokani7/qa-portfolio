## 1. 문서 목적

이 문서는 현재 개발된 VOC_Improve 프로그램의 실제 기능, 사용자 흐름, 품질 기준,
데이터, 외부 연동, 운영 제약 및 배포 조건을 제품 요구사항으로 정리한다.

향후 목표만 기술하는 일반적인 사전 PRD와 달리 다음 상태를 구분한다.

- **구현 완료**: 현재 소스와 웹 UI/API에서 사용할 수 있으며 자동 검증된 기능
- **운영 전 보완**: 기능은 구현됐으나 운영 배포 전에 강화해야 하는 항목
- **후속 범위**: 현재 제품 범위에 포함되지 않았으며 추후 검토할 항목

## 2. 제품 개요

### 2.1 해결하려는 문제

고객 VOC를 사람이 직접 읽고 요약·분류·개선안까지 작성하면 다음 문제가 발생한다.

- 장문·복합 불만의 핵심 내용이 누락될 수 있다.
- 불만 원인과 관계없는 일반적인 개선안이 생성될 수 있다.
- 담당자별 판단 기준이 달라 결과의 일관성과 재현성이 낮다.
- LLM 결과가 자연스럽더라도 사실성·안전성·실행 가능성을 객관적으로 설명하기 어렵다.
- 테스트 결과, 결함, 재시험, 사람 승인 근거가 분산되어 배포 판단을 감사하기 어렵다.

### 2.2 제품 비전

고객의 불만을 정확히 요약하고 원인에 맞는 정책 개선안을 생성하며, 그 결과와 처리 과정을
서로 다른 모델·정형 테스트·사람 검토로 검증할 수 있는 **설명 가능하고 감사 가능한 VOC
품질 운영 플랫폼**을 제공한다.

### 2.3 핵심 가치

1. **정확성**: 고객이 제기한 사실·원인·영향을 누락 없이 요약한다.
2. **실행 가능성**: 개선안이 원인과 직접 연결되고 담당자·조치·검증 방법을 포함한다.
3. **독립성**: 생성 모델과 독립 Judge를 분리해 자기평가 편향을 줄인다.
4. **추적성**: 6-Agent 처리 과정과 품질 근거를 실행 단위로 보존한다.
5. **안전성**: 개인정보, 프롬프트 공격, 위험 표현과 비정상 입력을 안전하게 처리한다.
6. **통제성**: 점수 하나가 아니라 필수 게이트와 사람 승인을 함께 적용한다.

## 3. 목표와 비목표

### 3.1 제품 목표

- 자연어 VOC 질문을 6-Agent 파이프라인으로 분석한다.
- VOC 요약과 정책 개선안을 분리해 제공한다.
- 단건, 배치, 오프라인 E2E, 라이브 E2E를 동일 품질 기준으로 관리한다.
- OpenAI 생성 결과를 Anthropic 등 독립 LLM Judge로 평가할 수 있다.
- 테스트 케이스, 실행 이력, Trace, 결함, 반복성, RAG, 보안을 웹에서 확인한다.
- Human Review를 통해 수정 요청·승인·반려·최종 배포 승인 근거를 기록한다.
- 모든 공식 실행의 결과와 증적을 다운로드·감사할 수 있다.
- 배포 기준을 충족하지 못하면 높은 평균점수와 관계없이 배포를 보류한다.

### 3.2 비목표

- 고객에게 직접 답변을 발송하는 CRM·상담 채널 기능
- VOC 원천 시스템에 정책 변경을 자동 반영하는 기능
- 법률·의료·보험금 지급 여부를 자동 결정하는 기능
- 무인 자동 배포 및 무인 최종 승인
- 현 단계에서 인터넷에 직접 노출되는 다중 테넌트 SaaS 운영
- 모델 학습·파인튜닝 및 벡터 데이터베이스 운영

## 6. 핵심 사용자 흐름

### 6.1 단건 VOC 분석

1. 사용자가 웹에서 VOC 질문을 입력한다.
2. 시스템이 입력 길이와 필수값을 검증한다.
3. Interpreter가 의도와 도메인을 해석한다.
4. Retriever가 관련 VOC와 정책 근거를 검색한다.
5. Summarizer가 요약 후보를 생성한다.
6. Evaluator가 후보를 평가·선택한다.
7. Critic이 누락·환각·위험을 검토하고 필요하면 요약을 보완한다.
8. Improver가 정책 개선안을 생성한다.
9. Critic이 개선안을 검토하고 필요하면 보완한다.
10. 웹은 요약, 개선안, Agent별 결과와 오류를 구분해 표시한다.

### 6.2 배치 품질검증

1. 사용자가 도메인과 테스트 데이터 세트를 선택하거나 파일을 업로드한다.
2. 시스템은 준비된 데이터 건수를 표시하고 실행 전 상태를 확인한다.
3. 기본 동시성 2건으로 각 케이스를 실행한다.
4. 기대 의도·키워드·필수 출력·금지 출력과 9개 품질 항목을 평가한다.
5. 결과를 PASS/FAIL/ERROR로 구분하고 JSON·CSV로 저장한다.
6. 실패 케이스는 상세 원인과 실제 응답으로 연결한다.

### 6.3 품질 실행과 외부 검증

1. 사용자가 자동 품질, 장애, 보안, E2E, 반복성 또는 종합평가를 실행한다.
2. 시스템은 `.env`에서 OpenAI·Anthropic 키의 설정 여부만 확인한다.
3. 공식 품질 실행은 실제 6-Agent 라이브 E2E와 외부 LLM Judge를 연속 수행한다.
4. 키가 누락되면 오프라인 결과로 대체하지 않고 필요한 설정을 안내한다.
5. 웹은 작업 ID, 진행률, 현재 단계, 취소, 오류, 최종 결과를 실행 카드별로 표시한다.
6. 실행 결과와 증적을 이력 데이터베이스에 색인한다.

### 6.4 Human Review와 배포 판단

1. 검토자는 날짜·회차·판정·검색 조건으로 자동 검토 큐를 좁힌다.
2. 큐에서 실패·보류·Judge 불일치·점수 차이가 큰 케이스를 선택한다.
3. 실제 질문, AI 요약·개선안, 내부 점수, Judge 응답과 검토 사유를 확인한다.
4. 검토자는 사람 점수, Judge 동의 여부, 의견과 결정을 기록한다.
5. 최종 배포 승인은 별도 체크로 명시한다.
6. 시스템은 기준 점수, 필수 게이트, 중대 위반, 사람 승인을 종합해 판정한다.

### 7.1 VOC 분석 및 멀티 에이전트

## 8. 품질 평가 요구사항

### 8.1 반드시 분리할 3가지 평가축

1. **불만 내용을 정확히 요약했는가**
   - 핵심 사실·원인·영향·복합 불만 누락 여부
   - 모호한 입력에서 근거 없는 추측 여부
   - 장문 압축과 감정·사실 분리 여부
2. **불만 원인에 맞는 개선안을 제시했는가**
   - 원인과 조치의 직접 연결 여부
   - 담당 주체·우선순위·기한·검증 지표의 구체성
   - 실제 정책·운영에 적용 가능한 수준인지 여부
3. **서로 다른 모델로 평가해도 품질이 유지되는가**
   - 생성 모델과 Judge 모델의 분리
   - 동일 데이터·동일 기준에서 점수와 판정 비교
   - 동일 모델 평가 대비 편향과 변동성 확인

## 9. 배포 판정 정책

### 9.1 기본 정책

- 기본 품질 기준은 95/100이며 웹 설정에서 저장·변경할 수 있다.
- 자동 품질, 보안, E2E, 독립 Judge, 중대 위반, 사람 승인을 각각 확인한다.
- 필수 게이트 하나라도 실패하면 평균점수가 높아도 배포를 보류한다.
- 중대 개인정보·보안 위반은 점수와 관계없이 즉시 보류한다.
- 실제 모델 검증 없이 오프라인 결과만으로 운영 배포를 승인하지 않는다.
- 사람 최종 승인 기록이 없으면 정식 배포 승인을 완료하지 않는다.

### 9.2 판정값

| 판정 | 의미 | 조치 |
| --- | --- | --- |
| APPROVED | 모든 필수 조건과 사람 승인을 충족 | 승인된 버전으로 배포 진행 가능 |
| HOLD | 점수·게이트·증적·사람 승인 중 하나 이상 미충족 | 결함 수정 후 동일 조건 재시험 |
| REJECTED | 중대 위반 또는 명시적 사람 반려 | 원인 분석과 설계 수정 후 신규 실행 |
| PENDING | 필수 결과 또는 검토가 아직 없음 | 필요한 검사·검토 완료 |

### 9.3 현재 판정 근거

- 자동 품질: 30/30 PASS
- OWASP 보안: 20/20 PASS
- 오프라인 E2E: 처리 1/1 PASS이나 평균 90.2점으로 기준 95점 미달
- CI 품질 게이트: 2/3 PASS
- 라이브 E2E: 평균 90.6점
- Anthropic Judge: 평균 89.0점
- 정식 사람 최종 승인: 미기록
- 결론: **HOLD**

## 11. 시스템 구조

### 11.1 논리 구조

```text
웹 브라우저 / MCP 클라이언트
          │
          ├─ web_app.py : UI, REST API, 백그라운드 품질 작업
          └─ main.py    : MCP 도구
                    │
                    ▼
grpc_server.VOCGRPCRuntime : 단일 오케스트레이터
                    │
     Interpreter → Retriever → Summarizer → Evaluator
                                      │
                               Critic / Refine
                                      │
                                  Improver
                                      │
                               Critic / Refine
                    │
                    ▼
OpenAI / Anthropic API · CSV 데이터 · 품질 평가기
                    │
                    ▼
qa_control_center.db · JSON/CSV · TXT/XML/HTML/JUnit · Word/PDF/ZIP
```

## 20. 단계별 로드맵

### 단계 1 — 품질 기준 충족

- 점수 하락 케이스의 요약 누락과 개선안 구체성을 수정한다.
- 동일 데이터로 오프라인·라이브 E2E와 Anthropic Judge를 재실행한다.
- E2E와 Judge 모두 95점 이상인지 확인한다.
- Human Review와 최종 배포 승인을 기록한다.

### 단계 2 — 교차검증 완성

- A·B·C·D 모델 조합을 한 번에 실행하는 실험 기능을 제공한다.
- 동일 데이터·평가기준·샘플 수를 고정한다.
- 점수 차이, PASS 일치율, 분산과 자기평가 편향을 비교한다.
- 실행 비교와 Word 보고서에 교차검증 결과를 포함한다.

### 단계 3 — 운영 보안·확장성

- TLS, 중앙 인증, 역할 기반 접근제어와 비밀관리 체계를 적용한다.
- 운영 DB, 백업·복구, 데이터 보존·삭제 정책을 수립한다.
- 부하·장시간·복구·장애 주입 테스트를 수행한다.
- 외부 알림과 운영 대시보드를 연동한다.

현재 제품은 다음 범위를 충족한다.
