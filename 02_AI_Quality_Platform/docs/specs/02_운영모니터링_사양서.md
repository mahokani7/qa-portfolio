# 02. 운영 모니터링 사양서 (📡 운영 모니터링 탭)

> 대상 기능(6): Prometheus·Grafana 통합(인프라) · 실시간 알림 상태(Golden Signals) · 운영 대시보드(요청/오류율/응답시간) · 트래픽 & 오류(Rate/Errors) · 응답시간 분포(Duration) · k6 성능 테스트 결과
> 대시보드 탭 함수: `render_monitoring_dashboard(ops_snapshot=None, is_current=True, run_dir=None, run_label="현재 실행")`.
> 공통 전제는 `00_공통_컨텍스트.md`. 각 섹션 독립 입력 가능.

## 공통 사항 (이 탭 전체)
- **현재 실행**: 라이브 Grafana 패널을 iframe 임베딩 + 알림 상태 실시간 조회.
- **과거 실행**: 그 실행에 **동결 저장된 스냅샷**(PNG + 지표)을 표시(`_render_frozen_ops`). 스냅샷 없으면 라이브 폴백.
- **스냅샷 저장**: `run_full.ps1`이 k6 직후 최신 실행 폴더에 자동 저장(수동 버튼은 제거됨).
- **핵심 모듈**: `quality/ops_snapshot.py` (Prometheus 조회 + matplotlib 차트 + 실제 Grafana 패널 캡처 + 저장/복원).

## 0) Prometheus · Grafana 통합 (인프라 — 다른 기능의 전제)
- **파일**: `docker-compose.yml`, `monitoring/prometheus.yml`, `monitoring/grafana/provisioning/*`, `monitoring/grafana/dashboards/*.json`, `app/`(FastAPI + prometheus_client), `performance/k6_test.js`.
- **목적**: FastAPI 앱이 노출하는 지표를 Prometheus가 수집하고 Grafana로 시각화. k6 부하테스트 지표는 remote-write로 Prometheus에 적재.
- **Docker 서비스 구성**:
  | 서비스 | 이미지/빌드 | 포트 | 역할 |
  |---|---|---|---|
  | `app` | build `.` (FastAPI) | 8000 | `/health` `/ask` `/metrics` |
  | `prometheus` | prom/prometheus | 9090 | app `/metrics` 스크레이핑 + **remote-write 수신**(`--web.enable-remote-write-receiver`) |
  | `grafana` | grafana/grafana | 3000 | 대시보드(admin/admin), 익명·임베딩 허용 |
  | `renderer` | grafana/grafana-image-renderer | (내부 8081) | 패널 PNG 렌더(보고서 캡처용) |
- **Grafana 필수 env**: `GF_SECURITY_ALLOW_EMBEDDING=true`, `GF_AUTH_ANONYMOUS_ENABLED=true`, `GF_AUTH_ANONYMOUS_ORG_ROLE=Viewer`, `GF_SECURITY_COOKIE_SAMESITE=none`, `GF_RENDERING_SERVER_URL=http://renderer:8081/render`, `GF_RENDERING_CALLBACK_URL=http://grafana:3000/`, **`GF_RENDERING_RENDERER_TOKEN`=renderer의 `AUTH_TOKEN`과 동일**(최신 Grafana는 기본 토큰 거부).
- **prometheus.yml**: `scrape_configs` job `ai_agent_quality_platform`, `metrics_path:/metrics`, `targets:["app:8000"]`(도커 네트워크 서비스명), `scrape_interval:15s`.
- **앱 노출 지표(prometheus_client)**: `ask_requests_total{status,agent_type}`(Counter), `ask_request_latency_seconds_bucket{le}`(Histogram, `_sum`/`_count` 포함). → `/ask` 처리 시 기록.
- **Grafana 프로비저닝**: `provisioning/datasources/datasource.yml`(Prometheus, uid `prometheus-ds`), `provisioning/dashboards/dashboards.yml`(자동 로드), `provisioning/alerting/rules.yaml`(Golden Signals 알림).
- **대시보드 2종**(자동 로드, uid 고정):
  - `ai-quality-ops` (slug 예: ai-agent) — 패널 id 1~7 (아래 3·4·5 기능).
  - `k6-performance` (slug 예: k6) — 패널 id 1~6 (아래 6 기능).
- **k6 실행**: `performance/k6_test.js`(vus 10, 30s, `/health`+`/ask`), remote-write로 적재:
  ```
  $env:K6_PROMETHEUS_RW_SERVER_URL="http://localhost:9090/api/v1/write"
  $env:K6_PROMETHEUS_RW_TREND_STATS="p(95),p(99),min,max,avg"   # ★ 없으면 p95/avg 미적재(기본 p99만)
  k6 run -o experimental-prometheus-rw performance/k6_test.js
  ```
- **수용 기준**: `docker compose up -d` 후 4개 컨테이너 healthy, `http://localhost:8000/metrics` 200, `http://localhost:9090/-/ready` 200, `http://localhost:3000/api/health` 200, `/render/d-solo/k6-performance/k6?panelId=1&...` → image/png 200.

## 1) 실시간 알림 상태 (Golden Signals)
- **데이터 소스**: Grafana Alerting API `GET {GRAFANA}/api/prometheus/grafana/api/v1/rules` (Basic admin:admin). 프로비저닝된 알림 규칙(`provisioning/alerting/rules.yaml`).
- **목적**: Google SRE Golden Signals(서비스 다운/높은 오류율/높은 응답 지연 등) 알림 규칙의 현재 상태를 카드로 표시.
- **로직**: `quality/ops_snapshot.py::fetch_alert_states() -> [{name, state, severity}]` — 규칙명에서 `"[Critical] 이름 — 설명"`의 이름만 추출. 실패 시 `[]`.
- **상태 매핑**: `firing→🔴 발동(error)`, `pending→🟡 대기(warning)`, `inactive/normal→🟢 정상(success)`.
- **대시보드 UI**: `_render_alert_cards(alerts)` — 규칙별 `st.columns` 카드(상태색). 과거 실행은 스냅샷의 `alerts` 사용.
- **수용 기준**: Grafana 미실행 시 경고 문구, 죽지 않음. 정상 상태면 3개 카드 모두 🟢. 규칙 없으면 "등록된 알림 규칙 없음".

## 2) 운영 대시보드 (요청/오류율/응답시간)
- **Grafana 대시보드**: `ai-quality-ops` 행 "🩺 서비스 헬스(Golden Signals)", 패널 id **1 서비스 상태(stat)**, **2 오류율(gauge)**, **3 p95 응답시간(gauge)**, **4 처리량 req/s(stat)**.
- **목적**: 요청률·오류율·p95 응답시간을 한눈에.
- **PromQL(참조)**:
  - 요청률: `sum(rate(ask_requests_total[1m]))`
  - 오류율(%): `100 * (sum(rate(ask_requests_total{status="error"}[5m])) or vector(0)) / clamp_min(sum(rate(ask_requests_total[5m])), 0.001)`
  - p95(ms): `1000 * histogram_quantile(0.95, sum(rate(ask_request_latency_seconds_bucket[5m])) by (le))`
- **대시보드 UI(라이브)**: `components.iframe(f"{GRAFANA}/d/ai-quality-ops/ai-agent?kiosk&refresh=10s&from=now-30m&to=now&theme=light", height=..., scrolling=True)`.
- **스냅샷(과거/보고서)**: `ops_snapshot.chart_golden_signals(out_dir)` — 요청률/오류율/p95 3분할 matplotlib PNG. `summary`에 `req_per_sec, error_rate_pct, p95_ms`.
- **수용 기준**: k6로 트래픽 주입 후 `now-30m` 창에 데이터 표시. 데이터 없으면 "No data"(죽지 않음).

## 3) 트래픽 & 오류 (Rate / Errors)
- **Grafana 대시보드**: `ai-quality-ops` 행 "📈 트래픽 & 오류", 패널 id **5 초당 요청률 — agent_type별(timeseries)**, **6 성공 vs 오류 요청 누적(timeseries)**.
- **PromQL(참조)**: `sum(rate(ask_requests_total[1m])) by (agent_type)`, `sum(ask_requests_total) by (status)`.
- **스냅샷**: `ops_snapshot.chart_traffic_errors(out_dir)` — 좌: agent_type별 요청률(rule_based/api_based 색상), 우: success/error 누적.
- **수용 기준**: agent_type(rule_based/api_based) 시리즈 분리, status(success/error) 시리즈 분리. 데이터 없으면 "No data".

## 4) 응답시간 분포 (Duration)
- **Grafana 대시보드**: `ai-quality-ops` 행 "⏱️ 응답시간 분포", 패널 id **7 응답시간 백분위 p50/p95/p99(timeseries, ms)**.
- **PromQL(참조)**: `1000 * histogram_quantile(q, sum(rate(ask_request_latency_seconds_bucket[5m])) by (le))` for q=0.50/0.95/0.99.
- **스냅샷**: `ops_snapshot.chart_duration(out_dir)` — p50/p95/p99 3선 그래프.
- **수용 기준**: 세 백분위 라인 표시. 데이터 없으면 "No data". NaN은 None 처리(`_query_instant`가 NaN→None).

## 5) k6 성능 테스트 결과
- **Grafana 대시보드**: `k6-performance`, 패널 id **1 총 HTTP 요청(stat)**, **2 오류율(stat)**, **3 p95 응답시간(stat)**, **4 VUs(stat)**, **5 응답시간 추이 avg/p95/max(timeseries)**, **6 초당 요청률 & 체크 성공률(timeseries)**.
- **데이터 소스**: k6 remote-write 지표(`k6_http_reqs_total`, `k6_vus_max`, `k6_iterations_total`, `k6_http_req_duration_{avg,p95,p99}`, `k6_http_req_failed_rate`, `k6_checks_rate`).
- **⚠️ 함정(반드시 준수)**:
  1. k6 duration 지표 **단위는 초** → ms 표기 시 ×1000.
  2. 엔드포인트(/ask,/health)별 시리즈 분리 → **sum()/max()로 집계**(총요청은 sum→600, p95는 max).
  3. 추세 지표는 매 플러시마다 리셋되는 게이지 → instant는 종료 시 0을 잡음. **`max_over_time(...[15m])`** 창 집계 사용.
  4. k6 실행 시 `K6_PROMETHEUS_RW_TREND_STATS`에 p(95)/p(99)/avg 포함해야 해당 지표 존재.
- **요약 지표(참조 쿼리)**: `sum(max_over_time(k6_http_reqs_total[15m]))`, `max(max_over_time(k6_vus_max[15m]))`, `1000*max(max_over_time(k6_http_req_duration_p95[15m]))`, `max(max_over_time(k6_http_req_failed_rate[15m]))`, `avg(avg_over_time(k6_http_req_duration_avg[15m]))`.
- **스냅샷**: `ops_snapshot.chart_k6(out_dir)` — 총요청/최대VUs/p95/오류율 카드형.
- **수용 기준**: k6 직후 총 요청 600(=/health 300+/ask 300), VUs 10, p95≈수십 ms, 오류율 0%.

## 스냅샷 저장/복원 (동결 — 과거 실행 재현의 핵심)
- **파일**: `quality/ops_snapshot.py`.
- **주요 함수(시그니처 유지)**:
  - `prometheus_available() -> bool`, `_query_range(expr, minutes, step)`, `_query_instant(expr)`(NaN→None).
  - `build_ops_snapshot(out_dir, minutes=30) -> {charts:{golden,traffic,duration,k6}, summary:{...}, alerts:[...]}` — matplotlib PNG + 지표 + 알림.
  - `grafana_render_available(timeout=30) -> bool`, `render_grafana_panels(out_dir, from_, to) -> [{section, panels:[{title, path}]}]` — 실제 Grafana 패널 PNG 캡처(위 3·4·5·6 패널 13개). `GRAFANA_PANEL_MANIFEST`에 (uid, slug, panelId, title, w, h) 정의.
  - `save_ops_snapshot(run_dir, minutes=30) -> dict` — `run_dir/ops_snapshot/`에 PNG + `snapshot.json`(summary+alerts+charts+grafana_panels 파일명) 저장.
  - `load_ops_snapshot(run_dir) -> dict|None` — 복원(`summary.frozen=True`). `has_ops_snapshot(run_dir)`.
- **과거 뷰 렌더**: `_render_frozen_ops(snap, run_label)` — 📸 캡처시각 안내 + 알림 카드 + 요약 지표(st.metric) + **grafana_panels 있으면 그걸, 없으면 matplotlib charts**.
- **수용 기준**: k6 직후 `save_ops_snapshot(run_dir)` → `ops_snapshot/`에 PNG 4(matplotlib)+13(grafana)+snapshot.json. 15/30분 후 `load_ops_snapshot`으로 같은 값 재현.

## 통합 수용 기준 (탭 레벨)
1. `run_full.ps1` 한 번으로 docker→app대기→k6(remote-write)→스냅샷 자동저장→대시보드→브라우저.
2. 현재 실행: 라이브 Grafana 임베딩 + 알림 실시간. 과거 실행: 동결 스냅샷(그 시점 값).
3. Grafana/Prometheus 미실행 시 각 섹션이 안내 문구로 폴백, 대시보드 죽지 않음.
4. k6 지표는 단위(초→ms)·집계(sum/max)·창(max_over_time)·TREND_STATS 4대 규칙 준수.
