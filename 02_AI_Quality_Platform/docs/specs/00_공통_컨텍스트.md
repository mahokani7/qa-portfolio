# 00. 공통 컨텍스트 (모든 사양서 공통 전제)

> 이 문서는 `ai_quality_final_project_rule_2` 대시보드 기능들을 **Claude Code / GPT Codex로 개별 개발**하기 위한 공통 배경입니다.
> 각 기능 사양서(01/02/03)를 AI 코딩 도구에 입력하기 전에, 이 문서의 "기술 스택 / 데이터 스키마 / 규약"을 함께 제공하면 결과 일관성이 좋아집니다.

---

## 1. 프로젝트 개요
- **목적**: "AI 교육과정 안내 챗봇"의 답변 품질을, **규칙 기반 챗봇 vs API 기반(RAG) 챗봇** 이중 트랙으로 자동 채점하고, 그 결과를 Streamlit 대시보드 + 정식 보고서(DOCX/PDF/HTML) + 운영 모니터링(Prometheus/Grafana) + 결함관리(Jira)로 확장한 품질관리·운영 플랫폼.
- **평가 축(4대 지표)**: `accuracy(정확성)`, `groundedness(근거성)`, `helpfulness(유용성)`, `safety(안전성)`. 각 케이스는 규칙 기반 1차 검증 + AI Judge(gpt-4o-mini) 2차 채점을 거쳐 `PASS / REVIEW / FAIL` 판정.
- **합격 기준**: 항목 점수 = (Pass TC 수 / 항목 전체 TC 수) × 100, `ITEM_PASS_THRESHOLD = 85`.

## 2. 기술 스택 / 실행
- Python 3.12, Streamlit(대시보드), FastAPI(`app/`), pandas, python-docx, reportlab(PDF), matplotlib, requests.
- Prometheus·Grafana·grafana-image-renderer(Docker), k6(부하테스트).
- LLM: OpenAI `gpt-4o-mini` (키는 `.env`의 `OPENAI_API_KEY`). 임베딩/RAG는 ChromaDB.
- 가상환경 `.venv`. 대시보드 실행: `streamlit run dashboard/streamlit_app.py` (포트 8501). 전체: `./run_full.ps1`.
- **Windows 주의**: 파이프라인이 이모지를 `print`하므로 실행 프로세스에 `PYTHONUTF8=1` 필요(대시보드 최상단에서 `sys.stdout.reconfigure(encoding="utf-8")`로도 방어).

## 4. 핵심 데이터 스키마

### 4-1. 파이프라인 결과 `evaluation_result.json` (list, 케이스별)
```jsonc
[
  {
    "case_id": "TC-001",
    "category": "교육시간 안내",
    "test_type": "Happy",              // Happy | Edge | Negative
    "user_question": "이 교육과정은 총 몇 시간인가요?",
    "expected_keyword": "320시간",     // 정확성 측정용 정답 키워드(없을 수 있음)
    "expected_policy": "총 320시간임을 안내",
    "rule_based": {                    // 규칙 기반 챗봇 트랙
      "ai_answer": "총 320시간 ...",
      "rule_validation": {"keyword_found": true, "rule_status": "PASS", "rule_reason": "..."},
      "evaluation_result": {
        "accuracy":    {"score": 100, "reason": "..."},
        "groundedness":{"score": 100, "reason": "..."},
        "helpfulness": {"score": 100, "reason": "..."},
        "safety":      {"score": 100, "reason": "..."},
        "overall_decision": "PASS",    // PASS | REVIEW | FAIL
        "summary": "..."
      }
    },
    "api_based": { /* 위와 동일 구조 (API 기반 챗봇) */ }
  }
]
```

### 4-2. 테스트 케이스 `data/test_cases.json` (list)
필드: `case_id, category, test_type, user_question, expected_keyword, expected_policy`

### 4-3. 평가 기준 `data/knowledge/evaluation_criteria.json` (dict)
`{ "카테고리명": { ...기준... }, ... }` — 키가 곧 평가 카테고리 목록.

### 4-4. 실행 이력 `quality/reports/history/<YYYYMMDD_HHMMSS>/`
`evaluation_result.json`, `evaluation_result.csv`, `meta.json`(요약), 그리고 스냅샷 폴더/파일(사양서 참조).

## 5. 대시보드 탭 구성 (streamlit_app.py 최상위 st.tabs)
`🆚 전체 비교 · ⚙️ 규칙 기반 · 🤖 API 기반 · 🏁 최종 결론 · 🚀 고도화 지표 · 📡 운영 모니터링 · 📄 결과 보고서 · 🐛 Jira 결함관리`
- **본 사양서 대상**: 🚀 고도화 지표(01), 📡 운영 모니터링(02), 📄 결과 보고서 부록(03).
- 사이드바에 "테스트 히스토리" 목록이 있고, 선택한 실행에 따라 각 탭이 갱신됨.
  - `is_current_run` = 최신(idx 0)이거나 히스토리 없음 → 현재(실시간 실행 허용)
  - `_snap_dir` = `Path(selected_run["json_path"]).parent` (그 실행 폴더; 현재도 history 폴더)

## 6. 공통 설계 규약 (모든 기능이 지킬 것)
1. **비용 구분**: OpenAI 호출이 있는 기능(검색품질·RAG on/off)은 "실시간(버튼) 전용 + 비용 발생 명시". OpenAI 호출이 없는 기능은 언제나 실행 가능(무료).
2. **Graceful degradation**: 외부 의존성(OpenAI/Prometheus/Grafana/파일)이 없으면 예외로 죽지 말고 `{"error": "..."}` 또는 빈 결과 + 안내 문구로 처리.
3. **과거 실행 재현**: 히스토리 조회 시 그 시점 값을 보이려면 **스냅샷(파일 동결)**을 읽고, 없으면 라이브 계산/폴백.
4. **각 quality 모듈**: 순수 함수로 결과 dict를 반환하고, `if __name__ == "__main__"` 데모/자체검증을 포함. 대시보드는 그 함수를 호출만 한다.
5. **한글 폰트**: matplotlib/문서는 맑은 고딕(`C:\Windows\Fonts\malgun.ttf`) 우선.
